# 微信每日新增岗位排版兼容设计

## 目标

解决微信公众号编辑器过滤页面级 CSS，以及 Markdown 导入器丢弃四级标题后，多个岗位连续显示、岗位名称和薪资缺失的问题。生成的文章采用人工导入 Markdown 的方式，导入后每个岗位应容易区分，岗位名称、薪资和详情链接应完整保留。

## 范围

- 以用户在 `article-wechat-import.md` 中确认的实际排版为标准，修改微信公众号文章 Markdown；HTML 本地预览同步相同摘要文案。
- Telegram 内容、抓取规则、岗位数量、排序和数据字段保持不变。
- 不开发小程序，不新增自动发布，不建设新的岗位落地页。
- 学历要求继续遵循现有规则：识别到学历时显示，未标明时隐藏整行。

## 公众号兼容原则

公众号后台可能移除 `<style>` 和 CSS class，因此不再把复制 HTML 作为本次发布主路径。实测还表明，公众号 Markdown 导入器会丢弃每个岗位使用的四级标题 `####`，导致该行中的岗位名称和薪资一起消失。

岗位标题改为普通粗体段落，岗位之间使用 Markdown 水平分隔线 `---`，不依赖卡片阴影、复杂布局或脚本。目标样式如下：

- 颜色：`#DCE3EC`
- 粗细：`1px`
- 上下保留阅读间距
- 只出现在相邻岗位之间，最后一个岗位后不显示

## 标准文章结构

文章顶部固定按以下顺序生成：

1. `YYYY-MM-DD 每日新增岗位公告`
2. `今日新增岗位：<实际新增总数>`
3. `搜索关键词：<当天所有关键词，以、连接>`
4. `覆盖城市：<快照中的真实城市，以、连接>`
5. 关键词趋势表
6. 城市优势组合
7. 趋势图
8. 今日新增岗位明细

顶部不再显示“样本”、关键词数量、城市数量或采集页数。关键词来自 `keyword_rows`，城市来自数据库快照头的 `cities`，不得把四个城市硬编码到模板。文章结尾固定为 `数据来源，仅供学习研究。`。

## 岗位结构

每个岗位按以下顺序展示：

1. 粗体岗位名称和薪资，中间使用 `｜` 分隔
2. 粗体公司名称
3. 工作地点
4. 学历要求（存在时）
5. 技能要求
6. `查看岗位详情 →`
7. 岗位分隔线（仅后面还有岗位时）

公众号导入 Markdown 时无法稳定保留单独的薪资颜色，因此岗位名称和薪资使用同一粗体行，优先保证内容完整。该行示例为 `**AI Agent 产品运营实习生｜250-350元/天**`。

## 链接要求

生成结果继续使用原始 `detail_url`。验收不能只检查文字是否呈蓝色，必须在公众号手机预览中点击并确认能够打开对应岗位页面。

如果公众号在复制时再次移除链接地址，本次修改不扩大为小程序或落地页开发，而是单独记录为平台发布链路问题。

## 实施边界

主要修改位置为 `src/jobflow/reports/wechat_article.py` 的文章数据与 Markdown 渲染逻辑；`src/jobflow/reports/multi_keyword_service.py` 负责把快照中的真实城市传入文章数据。实现应保留文章包文件结构，不改变 Telegram 内容。

测试应验证：

- Markdown 岗位标题不再使用四级标题 `####`。
- 岗位名称和薪资位于同一粗体普通段落，并使用 `｜` 分隔。
- 公司名称使用粗体普通段落。
- 两个岗位之间恰好有一条分隔线。
- 最后一个岗位后没有分隔线。
- 有学历和无学历两种岗位的字段顺序正确。
- `detail_url` 被正确转义并写入链接。
- 摘要显示具体关键词和具体城市，而不是数量。
- 城市列表非空、唯一，并且数量与 `city_count` 一致。
- 文章结尾严格使用 `数据来源，仅供学习研究。`。

## 验收流程

1. 本地生成只包含 3 个真实岗位的 Markdown 测试小样。
2. 将小样通过微信公众号的 Markdown 导入功能导入编辑器。
3. 确认岗位名称、薪资、公司、字段层级和分隔线均被保留。
4. 发送手机预览，逐个点击 3 条岗位详情链接。
5. 小样通过后再重新生成完整的 247 个岗位文章包。

本地 Markdown 内容正确不代表验收通过；公众号编辑器导入结果和手机预览是最终验收依据。
