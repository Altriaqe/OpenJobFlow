# V1.3.5 微信草稿内联排版修复设计

## 背景

微信公众号后台的人工文档导入支持 Markdown、DOC 和 DOCX，但官方草稿接口
`/cgi-bin/draft/add` 接收的是 HTML 正文。当前 `article.html` 使用 `<head><style>` 与
CSS class 完成卡片排版；微信保存草稿时会清理这些全局样式，导致自动草稿只剩无层级的
纯文本外观。

本设计保留已经确认的文章视觉样式，把实现改成微信草稿接口可以保留的内联 HTML。

## 目标与边界

### 目标

- 保留蓝色摘要区、趋势表格、岗位卡片、橙色薪资、公司名加粗和岗位间细分隔线。
- 标题、作者、统计字段、岗位字段、明文岗位链接和免责声明保持现有内容口径。
- 微信保存草稿后仍能看到清晰的岗位分组与视觉层级。
- 继续自动创建草稿，由用户在后台审核后手动发布。

### 不在范围内

- 不修改 Telegram 生成或发送链路。
- 不恢复公众号模板消息。
- 不自动正式发布公众号文章。
- 不依赖后台人工导入 Markdown。
- 不增加真实 AppID、AppSecret、Token、素材 ID 或服务器配置。

## 选定方案

采用“外观保持不变、底层改为内联 HTML”的方案。

生成器不再向草稿正文提供完整 HTML 文档，不输出 `<doctype>`、`<html>`、`<head>`、
`<style>` 或依赖 class 的样式。正文改为可直接提交给微信的 HTML 片段，每个需要视觉
表现的元素都携带自己的 `style` 属性。

标题与薪资的左右布局使用两列表格，而不是 `display:flex`。表格布局在公众号富文本中的
保留率更高，也能在窄屏手机上稳定展示。

## 排版结构

1. 顶部标题：日期与“每日新增岗位公告”。
2. 摘要卡片：今日新增岗位数、搜索关键词和覆盖城市，使用浅蓝背景与内边距。
3. 关键词趋势：使用带边框的三列表格。
4. 城市优势组合：使用段落列表，避免依赖浏览器默认列表样式。
5. 趋势图：继续使用上传到微信后的正文图片 URL。
6. 今日新增岗位：按关键词分组。
7. 单个岗位：
   - 第一行两列表格展示岗位名称与橙色薪资；
   - 公司名加粗；
   - 依次展示工作地点、可用时的学历要求、技能要求；
   - 岗位原始地址保持明文，并允许长链接换行；
   - 相邻岗位之间使用浅色细线和垂直留白分隔。
8. 文末免责声明：使用较小的灰色文字。

## 数据与调用链

```text
快照聚合数据
→ WechatArticleData
→ 生成 Markdown 人工包（保持现状）
→ 生成公众号兼容的内联 HTML
→ 替换 trend.png 为微信正文图片 URL
→ UTF-8 JSON 提交 draft/add
→ 用户在正式公众号草稿箱审核
```

Markdown 文件继续保留，供下载、归档和人工兜底使用；自动草稿只消费内联 HTML。

## 兼容与安全规则

- 所有业务文本继续经过 HTML 转义，岗位数据不能注入标签或样式。
- 原始岗位链接只接受现有校验过的 HTTP/HTTPS 地址。
- 不使用 JavaScript、远程 CSS、表单、iframe 或事件属性。
- 不在响应、日志或测试中输出微信凭据和完整素材 ID。
- 微信草稿创建失败仍记录为独立渠道失败，不影响 ETL 与 Telegram。
- 同日幂等和“不自动重试不确定结果”的规则保持不变。

## 测试与验收

### 离线测试

- 生成内容不包含 `<style>`、`class=`、`<head>` 或完整 HTML 文档外壳。
- 摘要区、趋势表、岗位分隔线、薪资颜色和明文链接均使用内联样式。
- 中文继续以 UTF-8 原文提交，不出现字面量 `\\uXXXX`。
- 恶意岗位文本经过 HTML 转义。
- 无学历字段时不渲染空学历行。
- Telegram 相关测试保持通过。

### 真实验收

1. 删除当前乱码且无样式的测试草稿。
2. 清理该日期对应的本地幂等记录。
3. 使用修复后的 API 创建一次草稿。
4. 在正式公众号后台确认中文、摘要卡片、趋势表格、趋势图、岗位层级、细分隔线、
   橙色薪资、明文链接和免责声明均正常。
5. 不正式发布，直到用户明确确认预览通过。

## 开放风险

微信仍可能清理少数不支持的 CSS 属性，因此真实验收以手机预览为准。若圆角等装饰属性
被移除，核心层级仍由边框、间距、字号、颜色和表格结构保证，不退回人工 Markdown 流程。
