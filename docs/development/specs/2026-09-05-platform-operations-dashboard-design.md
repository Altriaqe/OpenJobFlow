# JobFlow 平台运行与投放控制台设计

日期：2026-09-05
状态：设计已获用户批准，等待实施

## 目标

在现有采集、ETL、PostgreSQL、报告和双渠道投放链路之上，增加一个部署在 Ubuntu 的 Streamlit 控制台，用于查看八个阶段的状态、服务器运行证据、重启后的检查、一次受控恢复运行，以及按 `report_date` 分别手动投放 Telegram 和微信公众号草稿。

第一阶段只建设平台总览、运行中心和投放中心，不新增数据分析指标或复杂前端能力。

## 页面与阶段

页面包括平台总览、运行中心和投放中心。阶段固定为：数据源、采集任务、ETL 处理、PostgreSQL 数据层、数据分析 API、报告生成、Telegram 投放、微信公众号投放。状态固定为：未开始、开发中、已完成、已验收、观察中、异常。

阶段定义放在版本控制中的单个配置文件中；实际运行状态由检查、任务和投放证据计算，不用手工状态覆盖运行结果。

## 运行与投放

运行中心提供固定的服务器重启检查、一次完整恢复运行和检查历史。检查覆盖 Tailscale/SSH、Xvfb、Chrome、x11vnc、daily timer、PostgreSQL、API、`/health`、`/ready`、BOSS 登录态、最近 ETL、Telegram 和微信公众号状态。

投放中心要求选择明确的 `report_date`，分别执行 Telegram 和微信公众号操作。微信公众号只创建待审核草稿，正式发布仍由人工完成。外部请求结果不确定时禁止自动重试。

## 部署与权限

Streamlit 绑定 `127.0.0.1`，通过现有 SSH 隧道访问。第一阶段使用单管理员 Token，不开放公网端口，不提供多用户角色或权限页面。真实凭据、Cookie、素材 ID、草稿 ID 和服务器私有值不进入 Git 或知识库。

## 数据与验收

检查、恢复运行、每个恢复步骤和两个渠道的手动操作均写入 PostgreSQL，并使用日期、渠道和动作建立幂等边界。验收要求包括：检查失败阻断恢复；恢复步骤独立记录；重复操作不重复投放；微信不自动发布；页面只通过服务层访问数据和操作。

第一阶段不验收新的城市、薪资、技能或趋势图表，不验收公网访问、多用户权限、自动备份恢复、自动发布和复杂前端框架。
