# 微信文章包宿主机读取权限修复设计

## 背景

V1.3.2 已在 Ubuntu 完成真实微信测试号送达，但宿主机普通用户执行文章包检查命令时收到“权限不够”。原因是 `write_wechat_article()` 使用 `tempfile.mkdtemp()` 创建原子写入目录；该目录默认为 `0700`，在替换为最终 `wechat` 目录后仍保持该权限。

## 目标

- 最终 `wechat` 目录权限固定为 `0755`；
- `article.md`、`article.html`、`trend.png`、`manifest.json` 权限固定为 `0644`；
- 宿主机普通用户可以直接读取和复制文章包；
- 只有目录或文件所有者可以修改文章包；
- 保留现有原子替换、旧包恢复和异常清理行为。

## 非目标

- 不修改微信模板内容、发送接口、投递状态机或数据库；
- 不改变 `runtime/reports/<日期>/wechat/` 目录结构；
- 不为历史文章包递归修改权限；
- 不引入宿主机用户名、固定 UID/GID 或服务器专属 ACL。

## 方案

采用“写完后显式设置权限，再原子替换”的方式：

1. 在临时目录中写完四个文件；
2. 将四个文件分别设置为 `0644`；
3. 将临时目录设置为 `0755`；
4. 继续使用现有 `os.replace()` 将临时目录替换为最终目录；
5. 若替换失败，继续沿用现有旧目录恢复和临时目录清理逻辑。

不使用进程级 `umask`，避免并发请求之间互相影响；不依赖部署脚本事后 `chmod`，避免每次重新生成后权限再次退回 `0700`。

## 测试与验收

- 首次生成后，断言最终目录权限为 `0755`；
- 断言四个文件权限均为 `0644`；
- 覆盖已有文章包后重复断言权限；
- 保留现有四件套内容、无远程资源、非法图片拒绝和原子覆盖测试；
- Ubuntu 重新构建并生成文章包后，普通用户无需 `sudo` 即可执行文档中的 `find` 命令。

## 风险与边界

- POSIX 权限断言在 Windows 使用 `pytest.mark.skipif(os.name == "nt")` 跳过，并在 Linux/Docker 中验证精确的 `0755/0644`；Windows 仍运行文章内容和原子替换回归测试；
- 已生成的旧文章包仍保持原权限，只有重新生成的新文章包使用新权限；
- 文章包不包含 `appsecret`、OpenID、Token 等私密配置，因此允许宿主机本地用户只读访问。
