# 微信新增岗位卡片学历展示设计

## 背景

V1.3.3 微信每日新增岗位公告已经能够按关键词展示当天新增岗位，但岗位卡片目前只展示公司、城市、薪资、技能和详情链接。用户希望在每张微信公众号岗位卡片中增加学历要求。

当前上游原始 JSON 没有独立的学历字段，只有 `skills` 文本。Ubuntu `raw.job_records` 的真实数据检查表明，少量岗位会把“统招本科”等学历内容混在 `skills` 中，但该信息并不稳定。因此本次只做兼容性展示，不扩展抓取规则、数据库或每日快照结构。

## 目标

- 只修改微信公众号文章包中的岗位卡片。
- 从现有 `skills` 标签中识别学历要求。
- 识别不到学历时隐藏学历行，避免重复展示无效信息。
- 避免学历标签同时出现在“学历要求”和“技能要求”中。
- Telegram 的内容、发送链路和定时任务保持不变。

## 非目标

- 不修改第三方 BOSS 抓取器。
- 不新增 `education` 数据库列或迁移。
- 不回填历史数据。
- 不根据岗位名称、公司或其他文本推测学历。
- 不承诺所有岗位都能获得学历信息。

## 识别规则

文章生成器遍历每个新增岗位的 `skills`，按标签识别以下学历级别：

1. 学历不限
2. 中专
3. 高中
4. 大专
5. 本科
6. 硕士
7. 博士

标签允许包含额外修饰词。例如“统招本科”规范化为“本科”。识别过程只做明确关键词匹配，不进行语义推断。

识别时保留 `skills` 的原始顺序。一个标签包含明确学历词时视为学历标签，例如“统招本科”命中“本科”；“学历不限”必须整体优先匹配，不能被拆成其他结果。如果多个标签都能识别，卡片展示原始顺序中的第一个结果，并从技能文本中移除全部已识别的学历标签。没有任何命中时不渲染学历行。

## 展示设计

HTML 与 Markdown 使用相同顺序：

```text
岗位名称                         薪资
公司名称
工作地点：上海
学历要求：本科
技能要求：Java、Spring、MySQL
查看岗位详情 →
```

缺少学历时，卡片直接从“工作地点”进入“技能要求”，不显示占位学历。

如果移除学历标签后没有剩余技能，继续使用现有兜底文本“暂无明确技能标签”。

## 代码边界

- 在 `src/jobflow/reports/wechat_article.py` 内增加纯函数，负责从 `skills` 中返回规范化学历和剩余技能。
- `NewJobPosting`、数据库查询和快照模型保持不变。
- `_build_markdown` 与 `_build_html` 只消费纯函数的结果，不各自重复识别逻辑。
- 所有输出继续进行 HTML 转义，详情链接校验规则保持不变。

## 数据流

```text
raw skills
  → NewJobPosting.skills
  → 学历识别与技能过滤
  → 微信 Markdown / HTML 岗位卡片
```

## 异常与兼容处理

- 空标签、纯空白标签继续忽略。
- 未知标签继续作为技能展示。
- 完全缺失或无法识别学历时不渲染学历行。
- 本次不改变文章包文件名、目录权限、清单结构和新增岗位计数。
- 已生成的历史文章包不会自动重写；重新调用生成接口后才会应用新样式。

## 验收标准

1. `skills=("Java", "统招本科", "Spring")` 显示“学历要求：本科”，技能只显示“Java、Spring”。
2. `skills=("Java", "Spring")` 不显示学历行。
3. 仅有学历标签时，技能显示“暂无明确技能标签”。
4. 多个学历标签同时存在时展示原始顺序中的第一个结果，并从技能文本移除所有学历标签。
5. HTML 与 Markdown 仅在识别到学历时包含学历行。
6. Telegram 相关输出和测试保持不变。
7. 文章包仍包含 `article.md`、`article.html`、`cover.png`、`trend.png` 和 `manifest.json`。
8. 相关测试、完整离线测试、Ruff 检查和差异检查通过。

## 后续升级

如果需要提高学历覆盖率，应另开版本修改上游抓取器，增加独立 `education` 字段，并依次扩展 Adapter、`JobRecord`、数据库、每日快照和文章模型。本次实现不会阻碍该升级：未来只需把文章生成器的学历来源从标签识别替换为正式字段。
