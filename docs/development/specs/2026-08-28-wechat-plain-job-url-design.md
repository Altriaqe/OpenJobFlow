# 微信岗位明文链接设计

## 目标

微信公众号个人账号无法稳定保留外部超链接。岗位链接在 Markdown 导入后可能暂时可点击，但保存草稿时会被平台清除。本次调整不再生成岗位超链接，而是在每个岗位卡片中直接展示原始网址，确保保存草稿后网址文字仍可见并可复制。

## 范围

- 只调整微信公众号文章的 Markdown 和 HTML 输出。
- Telegram 推送内容、岗位抓取、ETL、排序、统计和定时任务保持不变。
- 不建设 GitHub Pages、独立岗位网页、小程序或新的公网服务。
- 不改变现有动态摘要、岗位分隔线、学历显示规则和文章结尾。

## 岗位卡片格式

每个岗位继续按以下顺序显示：

1. 粗体岗位名称和薪资，中间使用 `｜` 分隔。
2. 粗体公司名称。
3. 城市。
4. 学历要求；只有识别到具体学历时才显示。
5. 技能要求。
6. `岗位原始地址（复制后打开）：` 标签和完整原始网址。
7. 相邻岗位之间的分隔线。

链接区域示例：

```markdown
岗位原始地址（复制后打开）：
https://www.zhipin.com/job_detail/example.html
```

Markdown 不再把“查看岗位详情”文字和网址组合为可点击链接。HTML 不再使用 `<a href="URL">`，而是输出普通文字。网址是否被微信公众号自动识别为可点击内容不作为验收条件；必须保证保存草稿后网址仍然存在并可复制。

当 `detail_url` 为空时，整段“岗位原始地址”不显示，不生成空白地址或占位文字。

文章结尾固定使用：`岗位信息来源于公开招聘页面，仅供学习研究。请以招聘平台原始页面及招聘方实际信息为准。`。正文必须保留岗位名称、公司、城市、薪资、学历和技能等实质信息，网址只是补充入口，避免把文章做成纯跳转页。

## 安全与兼容

- 继续沿用现有 URL 校验，只接受包含有效主机名的 `http` 或 `https` 地址。
- Markdown 输出原始已校验网址，不添加 Markdown 链接语法。
- HTML 输出必须转义网址中的特殊字符，避免把数据解释为 HTML。
- 不写入 Token、Cookie、服务器地址或其他个人配置。

## 实施位置

- `src/jobflow/reports/wechat_article.py`：调整 Markdown 和 HTML 岗位链接渲染。
- `tests/reports/test_wechat_article.py`：验证明文网址、无超链接语法和无链接岗位。
- 相关开发文档：记录个人公众号外链限制和最终发布方式。

## 验收标准

- Markdown 包含 `岗位原始地址（复制后打开）：` 和完整网址。
- Markdown 不包含 `[查看岗位详情 →](...)`。
- HTML 包含岗位网址的普通文字，不包含该岗位的 `<a href=...>`。
- 有链接的每个岗位只输出一次网址。
- 无链接岗位不显示“岗位原始地址”。
- 其他岗位字段顺序、分隔线和摘要保持不变。
- 文章结尾使用已确认的数据来源与真实性提醒。
- Telegram 相关测试结果不变。
- 自动化测试、Ruff 检查和格式检查通过。
- 将测试小样导入微信公众号并保存草稿后，网址文字仍然存在。

## 非目标与后续选择

本次先解决公众号保存草稿后链接内容消失的问题，不保证读者可以直接点击网址。若明文网址的阅读体验仍不理想，可在后续独立版本中评估“阅读原文 + 公开岗位详情页”，但不与本次小修改绑定。
