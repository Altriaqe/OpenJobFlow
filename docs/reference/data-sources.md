# 数据源说明

## 当前来源

当前使用 [`eatmoreduck/boss-zhipin-scraper`](https://github.com/eatmoreduck/boss-zhipin-scraper) 在本机导出 BOSS 岗位 JSON 快照。首次验证基于该仓库提交 `26b272f`，最小导出结果为 30 条岗位。

这个工具独立于 JobFlow 运行。JobFlow 不包含它的代码，也不负责登录、验证码、Cookie 或平台风控，只读取手动指定的本地快照。真实快照不会提交到仓库，单元测试使用人工构造的数据。

## 字段映射

当前 Adapter 读取快照中的 `jobs` 列表，并映射以下字段：

| 来源字段 | JobRecord 字段 | 处理方式 |
| --- | --- | --- |
| `job_id` | `external_id` | 直接映射 |
| `title` | `title` | 直接映射 |
| `boss_name` | `company` | 该字段在当前导出中实际保存品牌名称 |
| `location` | `city` | 取第一个 `·` 之前的内容 |
| `job_link` | `detail_url` | 直接映射 |
| 固定值 | `source` | 写入 `boss_zhipin` |

快照结构仍需继续校验。来源字段缺失、类型错误和格式变化不能静默进入数据库。

## 使用边界

第三方仓库的 MIT 许可证只授权工具代码，不代表 BOSS 岗位数据获得开放许可。因此当前快照只用于本地 ETL 学习和结构验证，不随 JobFlow 部署，也不通过公开接口提供岗位明细。

公开部署只展示聚合结果。正式上线前需要替换为授权明确的商用 API 或其他合规来源，并核对数据保存期限、展示范围和服务条款。

## 替换方式

新数据源需要实现自己的 Adapter，将原始字段转换成 `JobRecord`。后续清洗、幂等入库、数仓分层和聚合接口继续复用，不与具体采集工具绑定。

## 后续动态采集与 AI 中台

当前阶段优先使用本地快照完成 ETL、质量校验和入库验证。后续接入动态 API 或合规动态采集时，只新增或替换 Source Adapter，不改变下游统一岗位模型、数仓分层和只读分析 API。

分析完成后的数据由语义查询 API 提供给 AI Summary Service。微信机器人只拥有只读 API 访问能力，用于查询聚合结果和发送总结，不直接访问数据库、不执行写操作，也不接触未授权的原始数据。动态查询字段、指标和筛选条件必须通过白名单控制。
