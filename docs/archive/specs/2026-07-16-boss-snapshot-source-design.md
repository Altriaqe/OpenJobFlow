# BOSS 岗位快照数据源设计

日期：2026-07-16

## 背景与目标

JobFlow 当前已经具备通用 JSON 请求边界和统一的 `JobRecord` 模型，但还没有真实岗位数据输入。直接使用 Requests 读取 BOSS 直聘页面时，页面字体反爬、登录状态和风控会降低数据可用性。当前阶段优先完成招聘数据工程链路，不自行实现或维护反爬对抗代码。

本设计选择将第三方项目 [`eatmoreduck/boss-zhipin-scraper`](https://github.com/eatmoreduck/boss-zhipin-scraper) 作为本机外部采集工具。JobFlow 只接收该工具导出的 JSON 或 CSV 快照，并由学习者亲手实现后续读取、转换、校验、去重、入库和查询功能。

本设计只补充本地学习阶段的数据接入方式，不放宽主设计中的云端部署与合规边界。该工具不计入主设计要求的“合规公开数据源”，也不会随 JobFlow 部署到公网。后续上线时仍需接入授权明确的商用 API 或其他合规来源。

## 选定方案

数据流如下：

```text
BOSS 直聘
→ 外部采集工具（本机、人工登录、低频运行）
→ 原始 JSON/CSV 快照
→ JobFlow 快照适配器
→ JobRecord
→ 清洗、校验与幂等去重
→ PostgreSQL
→ FastAPI
→ Streamlit
```

外部工具不并入 JobFlow 源码，也不作为 JobFlow Python 包的运行依赖。首次环境验证以已审查的提交 `26b272f` 为基准；后续升级前重新检查输出结构和测试结果。

## 组件边界

### 外部采集工具

- 负责启动独立 Chrome profile、复用用户主动建立的登录状态并导出原始快照。
- 单独安装和运行，不由 JobFlow 自动启动。
- 不把 Cookie、Token、Chrome profile 或调试端口信息传给 JobFlow。
- 不修改工具以绕过验证码、登录限制或平台风控。
- 发生验证、拒绝访问或异常时停止采集。

### JobFlow

- 只读取用户明确指定的本地 JSON/CSV 文件。
- 验证文件存在、编码、顶层结构和必要字段。
- 将来源字段转换为 `JobRecord`，不依赖外部工具的内部函数。
- 对未知字段保持兼容，对必要字段缺失给出包含文件位置和记录上下文的明确错误。
- 后续商用 API 通过新增适配器接入，不改变统一模型、数据库和服务层。

## 数据与仓库边界

- 真实采集快照、Cookie、Chrome profile、访问令牌和运行日志不得提交到 Git。
- 自动化测试使用人工编写的合成 fixture，不复制真实岗位详情或个人信息。
- JobFlow 文档注明第三方工具名称、仓库链接、MIT 许可证和使用版本。
- MIT 许可证只适用于第三方项目代码，不代表 BOSS 岗位数据获得开放许可。
- 对外展示以聚合分析为主，并保留来源名称和原始岗位链接。

## 错误处理

外部工具失败和 JobFlow 导入失败分开处理：

- Chrome 启动、登录、验证码和风控属于外部采集阶段错误，不由 JobFlow 重试或规避。
- 文件不存在、JSON 损坏、编码错误、顶层结构错误和必要字段缺失属于 JobFlow 快照导入错误。
- 单条脏记录不能被静默忽略；后续实现应记录失败数量和可定位的错误摘要。
- 原始快照结构发生变化时，适配器测试应失败，避免错误数据进入数据库。

## 测试策略

- 第三方工具先在 Windows 本机做一次最小环境验证，只导出少量岗位。
- 第三方仓库在当前 Windows 环境的离线测试结果为 `66 passed, 3 failed`；失败集中在 Chrome 进程与 profile 路径识别，因此不能假定 Windows 已受完整支持。
- JobFlow 单元测试只读取本地合成 fixture，不启动 Chrome、不登录 BOSS、不访问网络。
- 使用一份真实输出仅做人工字段核验，不将其提交到仓库。
- 适配器至少覆盖正常记录、缺少必要字段和损坏文件三类行为。

## 当前范围

当前阶段只接入一种 BOSS JSON 快照格式，不同时支持多个招聘平台、多个第三方爬虫或自动目录扫描。暂不实现外部工具调度、Chrome 容器化、Cookie 管理、验证码处理和公网实时采集。

## 后续替换

获得商用招聘 API 后，新增 API 采集适配器，将返回数据转换为同一个 `JobRecord`。快照适配器可以继续用于历史数据回放和故障恢复，PostgreSQL、FastAPI、Streamlit 以及清洗去重逻辑不需要因数据源替换而重写。

## 第一项验收

在 JobFlow 仓库之外完成第三方工具的 Windows 环境检查，并成功导出一份最小 JSON 快照。验收时只提供终端状态、字段名称和记录数量，不发送 Cookie、Token、完整请求头或 Chrome profile 内容。若 Windows 启动流程失败，先记录具体失败层级，再决定修复兼容性或改用其他本地环境。
